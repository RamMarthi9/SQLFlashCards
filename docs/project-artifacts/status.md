# SQLFlashCards Project Status

Last updated: November 25, 2026.

The account stage extends the flashcard flow with name-and-four-digit-PIN sign-up/sign-in and server-owned completion for each account. Learners explicitly mark topics completed or incomplete, filter the list, and retrieve their records after signing in from another browser connected to the same server. Legacy browser progress is an explicit import source only. All 14 syllabus topics count; six starter cards cover SELECT, DISTINCT, WHERE, NULL, INNER JOIN, and LEFT JOIN across three topics. The other 11 topics show Content coming soon and cannot be newly completed. SQLFlashCards remains a general SQL learning app; PostgreSQL for hosted accounts and SQLite locally do not select a teaching dialect. The current delivery work prepares Vercel HTTPS hosting, private Neon storage, and encrypted backups under the user's free-plan-only constraint. Production deployment and backup restoration are not yet verified. Review history, scheduling, and proficiency remain future work. The foundation was introduced in commit `59d115f`; subsequent changes are recorded below.

## Completed

- React and strict TypeScript foundation, Vite development/build setup, ESLint, Vitest, and content/learning interaction tests.
- Validated, bundled JSON catalogue with 14 topics, six starter cards, source references, and explicit syllabus mappings.
- Topic selection, question/answer reveal, Definition/Concept/Examples/Syntax panels, and previous/next navigation with safe boundaries.
- Direct card links, browser Back/Forward, missing-content recovery, and transient state reset on navigation or reload.
- Explicit Completed/Incomplete controls on topic and learning screens, All/Completed/Incomplete filters, and a summary over all active syllabus topics. Opening or revealing a card does not change completion.
- Name-and-four-digit-PIN accounts, sign-in/sign-out, server sessions, and separately owned topic progress in persistent SQLite. Client identity changes clear the prior account's visible state.
- An authenticated HTTP repository, server-side ownership/content validation, committed-save acknowledgement, version conflicts, focus/visibility refresh, and visible retry/error states; no anonymous-storage fallback.
- Salted PIN hashing with a separate server pepper, bounded authentication attempts, persistent throttling, and same-origin mutation checks. A four-digit PIN remains a limited credential, and account recovery is not implemented.
- Preserved legacy IndexedDB records for explicit import of the learner's own browser progress, without automatically assigning them to an account or overwriting account records.
- Responsive learning screens using the supplied mockup's lavender/purple visual direction, four coloured tiles, and join diagrams. The mockup's illustrative revision/proficiency values are not displayed as learner data.
- GitHub Actions configuration for type checking, linting, tests, and the production build.
- Vercel production adapter and deployment configuration, with explicit HTTPS origin, platform-specific client-IP handling, private settings, disabled preview API execution, and no temporary-file account storage.
- PostgreSQL account store for hosted use, retaining SQLite locally, with transactional initialization, shared attempt limits, and completion version checks. Real PostgreSQL checks are configured separately from local SQLite verification.
- Daily encrypted PostgreSQL-export workflow, authenticated encryption/decryption tooling, and guarded restoration into an empty database. Tooling is implemented; production backup activation and live restoration are not yet verified.
- Created and verified the private `RamMarthi9/SQLFlashCards-backups` repository for backup execution and artifact retention. The source repository is public; backup secrets and artifacts belong only in the separate private repository. Backup enablement remains off/unset and no production backup secrets are configured.
- A documented 14-topic SQL syllabus and example flashcard.
- A separate indexed SQL syllabus with numbered subtopics, learning outcomes, prerequisites, keyword lookup, and researched primary-source references.
- App copy, page metadata, and project guidance aligned with the user's general SQL learning scope.
- The user's Android/web visual reference, plus HLD and LLD documents describing the planned system.
- A single project-artifacts folder, an index, and maintenance guidance for future project work.

The private caller must pin the public reusable workflow and checked-out source to the same reviewed full commit SHA. It needs private secrets and `BACKUPS_ENABLED=true`; a passing backup/restore drill remains required before claiming protection is active. The user selected free plans only and new online accounts; no local-account migration or paid upgrade is authorized.

After hosting verification, continue expanding the six-card collection and settle review qualification/feedback before implementing review history and counts. Account recovery and stronger authentication remain follow-up decisions.

Review recording, revision rules, proficiency scoring, and Android packaging follow in later stages. See the [LLD delivery sequence](lld.md#delivery-sequence-and-boundaries).
